# 후속 실서버 연동 설계

현재 구현은 DB, 결제, 실인증 및 메시지 발송이 없는 프론트 프로토타입이다.

## API 교체

`services/repository.js`의 내보내기를 HTTP 구현으로 교체한다. 화면의 데이터 변환은 repository 계약을 유지한다. 비동기 전환 시 각 페이지의 로딩·오류 렌더링을 Promise 기반으로 확장해야 한다.

주요 계약: listEvents(filters), getEvent(id), listPosts(filters), getPost(id), listClubs(filters), searchAll(query), submitApplication(payload), getMemberDashboard(memberId). 등록·승인·학습·발급·알림 관련 메서드도 동일한 역할로 서버로 이동한다.

## 인증과 권한

통합 계정과 협회별 membership/role을 분리한다. 서버 세션 또는 안전한 인증 토큰, CSRF 보호, 모든 endpoint의 권한 검사를 수행해야 한다. 브라우저의 역할 select는 시연 기능이므로 실서비스 권한으로 절대 사용하지 않는다. 관리자 페이지 접근도 서버에서 제한해야 한다.

기업 ID는 정규화된 기업 마스터로 통합하고, 입력 당시 기업명 스냅샷은 별도 유지한다. 기업 산하 club을 별도 테이블로 두어 기업별 참여 통계를 합산할 수 있도록 한다. 공식 개인정보 처리 근거·보유기간은 정책 확정이 필요하다.

## 동시 접수

접수 마감과 정원, 팀 인원은 트랜잭션과 잠금으로 검증한다. memberId + kind + targetId의 활성 신청 중복을 서버에서 방지한다. 타임존과 날짜 경계는 서버 시간을 기준으로 한다. 요청 idempotency key를 사용하여 재전송으로 중복 접수되지 않도록 한다.

## 승인 이벤트와 알림

승인/반려/선발/접수/이수 요청 이벤트를 outbox에 저장한다. 템플릿 버전과 수신 동의·수신자를 확정한 후 백엔드 작업 큐가 알림톡·SMS·메일 공급자 API를 호출한다. 이벤트 ID + 채널 + 수신자 + 템플릿 버전으로 중복 발송을 방지한다. 공급자 오류는 지수 백오프로 재시도하고 최종 실패와 회신 상태를 관리자에 노출한다. 키는 서버 비밀 저장소에만 보관한다.

## 업로드·회원증·교육

- 업로드: MIME/확장자/크기 서버 검증, 악성 파일 검사, 비공개 저장소와 만료 다운로드 URL.
- 회원증: 서명된 불투명 토큰의 검증 endpoint. QR에 이름·전화번호 등 개인정보를 넣지 않는다. 현재 화면은 QR을 흉내 내지 않는 데모 카드다.
- 교육: 승인된 안전교육 영상 교체, 서버 학습 heartbeat, 시청 구간, 문항 결과, 수료 조건 및 변조 검증. 현재 스톡 현장 관찰 영상은 공인 교육이 아니다.
- 자격증: 합격 판정, 일련번호, 서명, 발급/재발급 감사 기록을 서버에서 처리한다.

## 협회 확장

association 설정의 theme/navigation/layoutVariant/enabledModules를 확장 지점으로 사용한다. 현재 C 방향만 구현했다. A/B/D의 원본이 없으므로 완성된 별도 시안은 만들지 않았다.

## 정책 확정 필요

가입 자격·기업 증빙·동호회 승인 조건, 참가비·환불·보험, 미성년자 여부, 자원봉사 선발·기수, 교육 인정 시간·수료 기준, 검증 자격의 법적 성격, 발급/재발급 비용, 개인정보·보유기간, 후원금·영수증·기업 혜택, 공식 자료 게시 권한을 협의해야 한다. 약관·정관·개인정보 문서는 법적 효력이 없는 검토용 양식이다.
