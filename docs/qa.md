## 검증 범위의 한계

대표 흐름과 화면 폭을 직접 확인한 결과이며 모든 브라우저/보조공학 조합의 접근성 인증이나 성능·보안 인증을 뜻하지 않습니다. 이미지 오류 대체 처리는 구현했으나 이번 브라우저 검사에서 의도적인 네트워크 장애를 주입하지 않았습니다. 다중 실제 사용자, 서버 권한, 결제·실제 발송·업로드·공인 교육 이수 검증은 백엔드 연동 후 별도 검증해야 합니다.

## 관리자 콘텐츠별 별도 편집 페이지
- `/admin/edit.php`에 콘텐츠 유형별 편집 화면을 제공합니다. 목록 제목/명칭 클릭은 편집 페이지로 연결합니다. 대회·회원·기업·동호회·교육·자격검증·게시물·배너·후원사·집행내역·알림 템플릿·자원봉사 모집의 필드와 목록 열을 각각 구성했습니다.
- 신청 검토, 안전교육 정정, 일괄 상태 변경, 알림 발송 전 확인도 별도 페이지입니다. 발송 이력은 수정하지 않는 상세 페이지로 제공합니다. 콘텐츠 편집용 모달을 제거했습니다.
- 행별 세로 점 메뉴는 수정/상태 변경/휴지통 이동을 제공합니다. 휴지통 목록에서 복구할 수 있으며, 감사 이력이 필요한 신청·발송 내역은 삭제 기능을 제공하지 않습니다.
- 콘텐츠별 저장 검증: 대회 일정 순서, 숫자/선택값, 내부 연결 경로, 반려 사유, 본문 문단, 체크 목록. 새로 만든 콘텐츠도 재수정·휴지통·복구 가능합니다.
- 안전교육 정정은 실제 학습 단계 수를 변경하지 않고 관리자 근거와 시각을 기록합니다.
- 목록 16개 화면과 편집 13종을 360px에서 점검: 렌더링 오류 및 페이지 가로 넘침 없음. 대회 저장, 세로 점 메뉴, 일괄 상태 페이지, 신청 검토, 알림 확인 페이지 연결 확인.
- 전체 테스트 32개 통과. PHP 및 JavaScript 구문 검사 통과. 저장은 기존 프론트 시연 저장소를 사용합니다.

- 선수등록의 이메일을 "이메일(ID)"로 바꾸고 비밀번호·비밀번호 확인(영문·숫자 포함 8~20자, 일치 검사)을 추가했습니다. 제출 시 비밀번호는 브라우저에서 SHA-256 해시로 바꿔 세션 저장소의 `account`(이메일·해시·이름)에만 저장하고 원문은 버립니다(저장소 덤프에 원문 없음 확인). 실제 서비스에서는 서버 측 해시(bcrypt 등)와 인증으로 대체해야 합니다.
- 로그인 페이지: 등록한 이메일(ID)과 비밀번호가 맞아야 로그인됩니다. 계정이 없으면 "등록된 이메일(ID)이 없습니다. 선수등록 후 로그인해주세요.", 불일치면 "이메일(ID) 또는 비밀번호가 일치하지 않습니다." 성공 시 마이페이지로 이동. 마이페이지 회원정보에 이메일(ID) 표시.
- 소재지: 시·도 셀렉트를 시·도 → 시·군·구 → 읍·면·동 3단 선택(한 줄 전체 폭, 모바일은 세로)으로 바꿨습니다. 목록은 `/assets/data/korea-districts.json`을 첫 선택 때 불러오며(`docs/asset-sources.md` 참고), 선택 값은 프로필에 저장되어 마이페이지에 "경기도 수원시 장안구 파장동"처럼 표시됩니다. `provinces` 목록은 데이터의 16개 시·도와 일치시켰습니다(광주·전남 → 전남광주통합특별시; 체육회 확인 필요).
- Playwright로 등록 → 로그아웃 → 오답/정답 로그인 → 마이페이지까지 자동 확인, 콘솔 오류 없음. 테스트 58개 통과.

## 선수등록 입력 안내 · 비밀번호 표시
- 비밀번호·비밀번호 확인 칸에 눈 아이콘 토글(표시/숨기기)을 달았습니다(로그인 페이지와 같은 구성).
- 두 비밀번호가 다르면 "비밀번호가 일치하지 않습니다."를 확인 칸 아래에 보여 주고 제출을 막습니다(같아지면 문구가 사라지고 제출 가능).
- 실시간 안내: 입력했거나 한 번 벗어난 칸은 조건에 맞지 않으면 바로 아래에 안내 문구가 나오고, 조건을 맞추면 사라집니다(이메일 형식, 비밀번호 규칙, 연락처·비상연락처 형식, 주민등록번호/여권번호 자릿수, 필수 미입력, 소재지 미선택 등). 제출 검사와 같은 문구(`fieldMessage`)를 씁니다.
- Playwright로 잘못된 값 입력 → 안내 표시 → 수정 → 안내 삭제 → 불일치 시 제출 차단 → 일치 후 등록 완료까지 확인. 테스트 58개 통과.

## 마이페이지 등록 정보 반영, 브레드크럼, 로그인 후 헤더
- 원인: 선수등록은 새 회원을 만들지 않고 데모 회원(`members[0]` 김스포츠)의 프로필을 덮어쓰는 구조인데, 덮어쓰는 항목이 참여 종목·연락처·소재지·등록 유형뿐이어서 이름·소속 직장·가입일·동호회는 데모 값이 그대로 남았습니다. 이름은 로그인 계정(`account`)에만 저장되고 화면은 회원 프로필을 읽었습니다. `register()`가 이름·소속 직장(빈값 허용)·`organizationId`·가입일(등록일)·`clubIds: []`까지 프로필에 반영하도록 고쳤습니다. 회원증·회원정보는 소속 직장이 없으면 "소속 직장 미등록"/"등록된 정보가 없습니다", 동호회는 회원의 실제 소속(`clubIds` 또는 `memberships`의 본인 항목)만 표시합니다.
- 브레드크럼: `heading()`의 그룹 기본값이 없어진 메뉴 이름 "체육회 서비스"였습니다. 기본값을 비우고, 그룹이 없으면 "홈 > 제목"만 표시합니다. 자격검증·학습·신청 페이지는 소속 메뉴(교육사업·주요사업·후원 등)를 명시했습니다.
- 헤더: 로그인 상태 처리(`interactions.js`)가 "로그인 → 마이페이지" 바꾸기와 로그아웃 버튼만 넣고 "선수등록" 링크는 두었습니다. 로그인하면 숨깁니다.
- 회귀 테스트 추가(등록 이름·소속·가입일·동호회 반영). 테스트 59개 통과.
- 추가: 선수등록 완료 화면은 새로고침 없이 그리므로 헤더가 "로그인 / 선수등록"으로 남았습니다. 헤더 계정 영역 처리를 `syncHeaderAccount()`로 분리해 등록 완료 직후에도 호출합니다. 가입일은 UTC가 아닌 로컬 날짜로 저장합니다.
- Playwright로 등록 → 로그아웃 → 오답 로그인(안내 문구) → 정답 로그인 → 마이페이지까지 라이브에서 확인, 콘솔 오류 없음.
