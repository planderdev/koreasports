## 구조와 실행

기존 PHP URL과 Vanilla JS를 유지했다. 관리자 전용 토큰(`admin-tokens.css`)과 셸, 데이터 질의, 목록, 드로어/일괄 처리, 편집기, 저장 어댑터를 분리했다. 관리자 JS는 읽을 수 있는 원본으로 정리했고 생성 번들만 압축한다. 기존 페이지별 녹색 UI 토큰은 관리자 경계에서 블루/중립색으로 매핑한다. 56px 상단바, 232/64px 사이드바, 36px 입력, 44px 기본 행, 148px 편집 라벨은 **프로젝트 지시서 수치**다.

```powershell
npm ci
npm run build
npm test
npm run dev:editor  # 편집기 번들 watch
php -S 127.0.0.1:8080 -t .
```

배포 시 `assets/js/generated/`도 포함한다. PHP 실행에는 Node 프로세스가 필요 없다. Tiptap 3.31.3의 core/pm/StarterKit 및 표·이미지·색상·정렬 확장을 lockfile로 고정했다. StarterKit에 포함된 Link/Underline/UndoRedo를 중복 등록하지 않았다. 공개 상세 페이지에는 Tiptap 본체 대신 작은 JSON 렌더러와 sanitizer를 사용한다.

## 실제 수정한 문제

- DOM 문자열 검색/정렬을 데이터 → 필터 → 정렬 → 페이지 분할로 교체. 검색 제출과 URL 동기화, KST 날짜 경계, 20/50/100개 보기, 선택 ID 집합을 분리했다.
- 페이지를 이동해도 선택 유지, 검색 조건 변경 시 초기화. 현재 페이지와 전체 검색 결과를 구분한다. 대량 ID를 URL로 전달하지 않는다.
- 일괄 처리 대화상자에서 대상과 사유를 확인하고, repository가 반환한 실제 성공/실패와 재시도 대상을 표시한다. 휴지통/복구, 선택 CSV의 BOM/escaping/수식 방지를 유지했다.
- 목록 제목은 정식 수정 페이지로, 빠른 상세는 드로어로 연결한다. 회원 관련 신청과 실제 처리 이력을 보여준다.
- 저장소 쓰기 실패를 삼키던 동작을 수정해 오류를 알리고 입력을 유지한다. 신규 게시물이 첫 번째 원본 게시물의 본문/출처를 상속하던 동작도 제거했다.
- Tiptap 초기 정규화로 원문이 변경되었다고 판단하지 않도록 초기 정규화 JSON을 기준으로 비교한다. 제목만 수정할 때 본문 필드를 저장 패치에서 제외한다. 원본 보존 노드의 빈 편집기 text 때문에 제목 저장이 막히던 경우도 수정했다.
- 이미지가 IndexedDB에 저장되어도 CSP에서 복원용 blob 이미지를 차단하던 문제를 발견하고 `img-src`에 blob을 허용했다. 영구 데이터에는 blob URL을 저장하지 않는다.
- 관리자 모바일 헤더가 공통 workspace의 세로 배치 규칙을 상속하던 충돌을 원본 관리자 규칙에서 해결했다. 동일한 최상위 CSS 선택자 선언도 합쳤다.
- 알림 템플릿 변수 입력과 미리보기/수신 선택을 연결하고 실제 발송 성공으로 표시하지 않는다. 저장 결과는 발송 대기다.
- 배너 노출 순서/상태는 사용자 메인에 반영된다. 사용자 본문과 관리자 미리보기는 `prose.css`를 공유한다.

## 본문과 파일 정책

새 본문: `bodyJson` + `bodySchemaVersion:1`을 기준으로 HTML과 plain text를 함께 만든다. 읽기 우선순위는 지원하는 새 JSON, 저장된 HTML, 기존 문단 배열이다. 일반 문자열은 HTML로 해석하지 않는다.

기존 원본 HTML은 `originalBlock` 보존 노드로 감싼다. 원문 내부를 Tiptap 기본 문단으로 강제 변환하지 않는다. 원본 블록과 새 문단을 함께 보존하며, 제목/상태만 저장할 때 기존 `bodyHtml`, `body`, `originalBody`는 그대로다. 원본 보존 블록 내부의 개별 글자 편집은 제공하지 않는다. 블록 이후에 내용을 추가하거나 블록을 명시적으로 교체할 수 있다. 지원하지 않는 JSON 스키마는 편집기 로드/저장을 차단한다.

허용 태그/속성 목록과 DOMPurify를 적용하며 script, 이벤트 속성, javascript URL, 폼/iframe/object/embed를 제거한다. 보존과 보안 정제는 구별된다. 최초 표시만으로 원본 파일을 수정하지 않는다. 원본 백업/재수집은 기존 `docs/research/kowsc`, `assets/js/source-content.js`, `scripts/import-kowsc-content.py` 흐름을 그대로 유지한다. 변환은 `initialContent()`에서 반복 가능하다.

본문 이미지는 PNG/JPEG/WebP/GIF 최대 10MB, 다운로드 첨부는 문서/ZIP 최대 20MB를 별도 관리한다. IndexedDB의 안정적인 ID로 파일을 저장하고 페이지별 blob URL을 복원한다. 형식/크기 오류, 저장 중 상태, 이미지 재시도를 지원한다. 원본 서버 첨부 링크도 유지한다.

## 검증 결과

- `npm test`: 50개 통과. 필터/숫자 정렬/KST/페이지 선택 범위, 부분 실패, 저장소 실패, 신규 본문 독립성, 실제 Tiptap JSON 왕복, 표/링크/굵게/이미지 속성, 원문 보존, sanitizer 등을 포함한다.
- `npm run build`: 성공. 동일 입력으로 재빌드 시 생성 결과 동일. 오래된 hash chunk를 빌드가 제거한다.
- 관리자/공통 PHP 구문 검사 통과. `git diff --check` 통과.
- 브라우저: 대시보드, 회원, 기업, 동호회, 대회, 신청, 교육, 자격, 안전교육, 봉사 지원/모집, 게시물/배너, 후원사/집행내역, 알림의 16개 메뉴 및 게시물 편집 실행. 확인한 메뉴에서 JS 콘솔 오류 없음.
- 목록 1920/1440/1280/768/390px: 문서 전체 가로 overflow 없음, 상단바 56px, 사이드바 232px 또는 64px. 표는 내부 스크롤. 편집 1440/768/390px 확인.
- 160건(원본159 + 검증용1) 목록: 현재 페이지 20건 선택 → 다음 페이지에서도20 유지 → 검색 결과160 선택 → 검색 변경 후0, 결과1로 초기화. 상태 변경 결과 성공1/실패0 확인.
- 한글 본문 작성 → 굵게 → 표 삽입 → undo/redo → 저장 → 새로고침 → 미리보기 확인. 사용자 상세에서 동일 본문/표 출력 확인.
- PNG 업로드 → 저장 → 재편집과 사용자 상세에서 IndexedDB 이미지의 blob URL 복원 확인. 문서 첨부의 다운로드 blob 링크 확인. 잘못된 TXT 이미지 업로드 거부 및 재시도 표시 확인.
- 원본 `kowsc-article-40` 제목 저장 후 재로드에서 본문 텍스트 유지. 자동 테스트에서는 표/이미지/줄바꿈 보존 노드도 검증.
- 미저장 내부 이탈 확인 → 임시저장 후 이동 → 복구 → 저장 확인. 빈 제목 저장 시 필드 오류와 입력 복구 확인. 실제 발송은 실행하지 않았다. 휴지통 이동/복구 성공1건씩을 확인하고 검증용 게시물은 다시 휴지통으로 정리했다.

## 연동 경계와 확인하지 못한 항목

- 현재 repository는 브라우저 세션 오버레이이며 서버 인증/권한/DB/감사 로그가 아니다. 미디어·임시저장·환경설정은 이 브라우저의 IndexedDB/localStorage에 있다. 다른 사용자/브라우저와 공유되지 않는다.
- HTTP repository, 서버 업로드·파일 서명/악성코드 검사, 서버 sanitizer, 실제 메시지 공급자 및 수신 동의 검증은 서버 연동 범위다. 브라우저의 MIME/확장자 검사는 서버 검증을 대체하지 않는다.
- 실제 Windows IME 조합 이벤트, Word/Excel 각 버전의 클립보드 조합, 모든 모바일 기기의 파일 선택기는 검증하지 못했다. 한글 문자열 입력/줄바꿈과 지원 HTML/표 변환은 검증했다.
- 카페24 로그인 뒤 관리자 화면은 접근하지 않았다. 공개 공식 가이드의 검색 대상/기간/목록 선택/상태 변경/휴지통 패턴을 참고했으며 수치 실측으로 주장하지 않는다.
